# KUKO WAY QR artwork

Standalone QR artwork for **https://daily-trainer-app.vercel.app/**. It is separate
from the app: nothing in `platform/` is changed, and only the brand fonts in
`platform/app/fonts/` are read.

## Approved: "Movement Within", Concept A

`out/movement-within-A.png` (2400×3000) is a real QR code with a person
performing a fascial exercise drawn into its light space. The dark modules run
up to the body's outline, and sage fascial lines follow the spiral and jaw
pathways. The palette is KUKO WAY ivory, charcoal, forest, sage and moss.

**Code**
- Generated by segno from the exact URL: version 6, level H (~30% error
  correction), mask 2, 4-module quiet zone.
- The finder, timing, alignment and format modules are always solid and are
  never covered. The figure sits in the centre; version 6's only alignment
  pattern is at the lower right.
- A very faint "fascial web" of tonal pores under the body restores most module
  values there.

**Files**

| File | Role |
|---|---|
| `movement_within.py` | Generates the artwork (Concept A and the unapproved Concept B) |
| `verify_movement_within.py` | Module audit and decoding report |
| `generate_forest_qr.py` | Person segmentation (`person_mask`) from the reference image |
| `generate_qr_art.py`, `verify_qr.py`, `verify_real_qr_sasho.py`, `make_real_qr_sasho.py`, `add_background_qr_sasho.py` | Shared helpers: decoders, stress variants. `verify_qr.py` reads `out/qr-meta.json` when it loads |
| `sasho-qr-code-new-2.jpg` | Reference image the person is taken from |
| `out/qr-meta.json` | Required input for `verify_qr.py` |
| `out/movement-within-A.png` | Approved artwork |
| `out/movement-within-A-verification.md` | Short decode check of the approved PNG |
| `out/movement-within-verification.md` | Full verification report (A and B) |

**Reproduce** (Python 3.13 with `segno zxing-cpp opencv-python pillow numpy`):

```bash
python movement_within.py          # -> out/movement-within-{A,B}.png (+ -1200 and -compare previews)
python verify_movement_within.py   # -> out/movement-within-verification.md; exits 1 on any failure
```

Running these from only the files listed above regenerates `movement-within-A.png`
byte for byte.

**Verification**
- zxing-cpp and OpenCV `QRCodeDetector` must both return the exact URL.
- The print file is decoded natively and scaled to 600–2800 px wide.
- The 1200 px review file is decoded under blur, JPEG q=30, rotation, tilt,
  low contrast and brightness, noise, and white or dark surroundings.
- The module audit finds no wrong structural or open-code modules. Near the
  figure, 3.0% of the symbol reads wrong.

**Limitations**
- At about 150 px wide, OpenCV can fail; zxing-cpp still decodes.
- This is software decoding only, not a phone-camera test. Before printing,
  scan a proof with the iOS and Android camera apps.

The PNG previews are covered by the repository's `*.png` ignore rule. Only the
approved `movement-within-A.png` was force-added.

## Edition 1: Facial Fascia (dark card)

A standalone QR artwork that opens **https://daily-trainer-app.vercel.app/**.
It is separate from the app: nothing in `platform/` was changed. The only thing
taken from `platform/` is its brand fonts, which are embedded in the SVG, and its
Playwright Chromium, which renders the PNGs.

## Outputs (`out/`)

| File | Size | Use |
|---|---|---|
| `kuko-way-qr.svg` | 1200×1500 viewBox | Vector master, with the brand fonts embedded |
| `kuko-way-qr-print.png` | 3000×3750 | Print, 10×12.5 in at 300 dpi |
| `kuko-way-qr.png` | 1200×1500 | General sharing |
| `kuko-way-qr-social.png` | 1080×1350 | Instagram and Facebook 4:5 post |
| `qr-meta.json` | n/a | Encoded matrix and geometry, used by the verifier |

## Design

- **The QR code** is version 5 at error-correction level **H** (37×37 modules, byte mode). It is drawn one module at a time in `#181917` on a warm-white `#F5F0E6` card. The three finder patterns keep the standard 7/5/3 geometry and only have slightly rounded corners.
- **Quiet zone:** 5 modules of plain light space on every side. The spec asks for at least 4.
- **Centre medallion:** a sage disc with a face contour and two lifting strokes. It clears a 7×7 block of modules (49 of 1,369, about 3.6%). Error-correction level H can repair about 30%, and the timing, alignment, format and finder areas are not touched.
- **Facial artwork:** the face contour (temples, cheekbones, jawline, chin, forehead) and the sage fascial-lift pathways all sit *behind* the opaque card:
  - cheek sweeps that run up and outward,
  - a forehead fan,
  - jaw-sculpting strokes,
  - fingertip touch points.

  The strokes seem to flow out from the code, but none of them crosses the symbol or its quiet zone.
- **Palette:** night `#181917`, warm white `#F5F0E6`, sage `#7D8B72` and moss `#AAB39C`. These are the app's own tokens from `platform/tailwind.config.ts`.

## Reproduce

```bash
pip install segno zxing-cpp opencv-python pillow numpy   # a venv is recommended
python generate_qr_art.py     # → out/kuko-way-qr.svg + out/qr-meta.json
node render_png.mjs           # → PNGs (uses platform/node_modules Playwright Chromium)
python verify_qr.py           # decode + audit; exits 1 on any failure
```

To change the destination, edit `URL` in `generate_qr_art.py`, then run all three steps again. A longer URL may produce a larger QR version, so check the layout afterwards.

## Validation report (2026-10-20)

`verify_qr.py` checks all three PNGs with two decoders. Neither of them shares code with segno, the encoder:

- **zxing-cpp**, the ZXing engine that most Android scanning libraries are built on
- **OpenCV `QRCodeDetector`**

What it checks:

1. **Module audit.** It samples every module centre of each render and compares it with the encoded matrix. Result: **0 wrong modules outside the medallion** in all three PNGs. 24 modules inside the medallion differ, all inside the 7×7 block cleared on purpose.
2. **Decoding.** Each PNG is decoded as rendered, then under these stress variants:
   - downscaled to 1080, 600, 390 and 300 px wide (390 px is an iPhone screen width)
   - Gaussian blur
   - JPEG quality 30
   - rotated 17°
   - perspective tilt
   - contrast reduced to 55%
   - brightness reduced to 60%
   - Gaussian noise

**Result:** both decoders returned exactly `https://daily-trainer-app.vercel.app/` in every one of the 36 cases.

## Limitations

- The tests decode rendered images in software. They are not a scan with a physical iPhone or Android camera. Before printing, do a final scan with each phone's camera app, both off a screen and off a printed proof.
- Print the QR card at least about 2.5 cm (1 in) wide. In the full poster, the card is 55% of the width.
- Keep the card warm white. Don't invert it (light modules on dark) and don't recolour the modules in a low-contrast tone.
- The fonts are embedded as WOFF2 inside the SVG. Browsers render them correctly, but some vector editors (older Illustrator or Inkscape versions) may substitute the fonts when they open the file. This affects only the text, never the QR code.
- If you scale the artwork, keep the card and the space around it intact. Cropping into the card would eat into the quiet zone.

## Edition 2: Facial Fascia Map (2026-10-20)

This is a light, editorial variant: a line-art face with the QR code at its heart. The original artwork above and its source files are unchanged. This edition only adds new files.

| File | Purpose |
|---|---|
| `out/kuko-way-qr-face.svg` | Vector master |
| `out/kuko-way-qr-face-print.png` | 3000×3750, for print |
| `out/kuko-way-qr-face.png` | 1200×1500 |
| `out/kuko-way-qr-face-social.png` | 1080×1350 |
| `out/kuko-way-qr-face-preview.png` | Original, new edition and phone-width view side by side |
| `out/face-verification.txt` | Full verifier output |
| `generate_qr_face.py`, `render_face.mjs`, `verify_qr_face.py` | Source for this edition |

```bash
python generate_qr_face.py && node render_face.mjs && python verify_qr_face.py
```

## Design

- **Composition:** a calm, symmetrical face with closed eyes. The QR card sits where the mid-face would be. The eyes and brows are above the code, and the lips and chin are below it, so the code literally *is* the centre of the face.
- **Line work** is in charcoal `#22231F` on warm ivory `#ECE5D7`:
  - hair with a centre part, swept back over the temples
  - ears, brows and lashes
  - a nose bridge that disappears behind the card
  - lips
  - a contour that runs from the temples over the cheekbones to the jaw and chin
- **Muscle-fibre hatching** uses hairlines at 30% opacity, following the frontalis, orbicularis oculi and oris, zygomatic and masseter pathways.
- **Fascial maneuvers** are sage `#7D8B72`, used sparingly. Each one starts with a dot (the touch point) and ends with an open chevron (the direction):
  - forehead lift
  - brow-to-temple glide
  - cheek-to-temple lift
  - chin-along-jaw-to-ear sculpt
  - mouth-corner lift

  The cheek, jaw and mouth pathways all converge on the card, which leads the eye to the code.
- **Inset marks:** thin registration-style corner marks around the card frame it like an inset on an anatomy plate, so it doesn't look like a sticker.

## QR protection

- **The QR layer is reused, not regenerated.** It is the output of `generate_qr_art.qr_layer()` (579 module rects, 3 finder patterns, the medallion and the same warm-white card), placed with only a whole-pixel `translate(0 64)`. `generate_qr_face.py` asserts that the encoded matrix equals the one in the original `qr-meta.json`.
- **Artwork stays outside the code.** All decorative paths are drawn *before* the opaque card, and the corner marks sit outside it. Nothing reaches the symbol or its 5-module quiet zone.

## Validation (`verify_qr_face.py`)

| Check | Result |
|---|---|
| QR layer markup is byte-identical in the original and new SVG | **PASS** |
| Module audit of all 3 PNGs: wrong modules outside the medallion | **0** |
| zxing-cpp and OpenCV decoding, 3 files × 12 variants (36 cases) | **All return `https://daily-trainer-app.vercel.app/`** |

The 12 variants per file:
- as rendered
- downscaled to 1080, 600, 390 and 300 px
- blur
- JPEG quality 30
- 17° rotation
- perspective tilt
- low contrast
- low brightness
- noise

**About the pixel diff.** The verifier also reports a raw pixel diff of the 1× card region against the original: 655 module-edge pixels differ. These come from Chromium's 256 px raster tiles. In the original, the tile seams fall on module rows 0–1 and 18–19 (y = 512 and 768). After the shift they fall elsewhere, so those edges are anti-aliased slightly differently. They are rasteriser artefacts, not content changes: the markup is identical and every module centre matches.

**Limitation.** As before, this is software decoding, not a scan with a real phone camera. Do a final camera-app check on iOS and Android before printing.
